# AI 味终检（交付前必跑）

> **与「13 项交付自检」的分工**：
> **13 项自检问「该做的都做了没有」，本文件问「这词像不像人写的」。两者都过才算完。**
> 13 项全过的词，照样可能满是 AI 味。
> 来源：症状清单合并自 CC0-1.0 项目 `bitwize-music-studio/claude-ai-music-skills`
> 的 `skills/voice-checker`（Class 1–7）与 MIT 项目 `jtydhr88/lyric-writing-skills`
> 的 `lw-ai-tell-audit`（八条枚举）。本文件为合并改写。

---

## 0. 核心命题

> **AI 写的词不是「用词不好」，是「没有人做过选择」。**
>
> 它写出来的四段词语法正确、押韵工整、意象丰富，
> **而这四段可以属于任何一首歌。**

**共同点**：**规则被当成了要满足的条件，而不是要做的选择。**
这正好就是 AI 味的定义。

## 1. ★ 十二条症状（逐条打勾，不要凭整体印象）

| # | 症状 | 判定信号 | 可自动 |
|---|---|---|---|
| **1** | **名词全是抽象的** | 单行/单联出现 **≥3 个抽象名词**（hope / dreams / light / 时光 / 远方 / 梦 / 自由）；抽象名词当清单列举（"hope, dreams, and light"）；抽象名词做抽象事（"truth shines through the darkness"） | ✅ 词表统计 |
| **2** | **结构对称到死** | 每段行数、字数、句法完全镜像；每行都是同一套「主谓宾」；Pre-Chorus 段段同构 | ✅ 每段字数方差 |
| **3** | **什么都解决了，没有悬着的** | 难过→释怀→祝福走完整；无挫折、无含糊；Bridge 必是"黎明前最黑"且保证解决 | ⚠ 半自动 |
| **4** | **没有具体细节** | 全曲只有通用意象；**无专名、无地名、无触感/气味/声音/日期/物件**；可以是任何人、任何地、任何时 | ⚠ |
| **5** | **套话升级** | 见 §1.1 英文套话清单 / 中文滥意象表 | ✅ 词表统计 |
| **6** | **口语里语法太完美** | 该用缩写处全写全（`I am` 而非 `I'm`、`do not` 而非 `don't`）；**每行都是完整句，没有碎片、没有停顿、没有自我打断** | ✅ |
| **7** | **过度解释隐喻** | 第 N 行给意象、第 N+1 行立刻解释（`Like a river running dry / My love has disappeared`）；用"meaning" "just like" 去解码上一句 | ✅ |
| **8** | **没有视角和时间** | 人称代词漂移；没有时态锚点（何时发生、谁在说） | ⚠ 代词检测可辅助 |
| **9** | **倒字不管** | 有旋律时逐字查（见 `tone-check.md`） | ✅ 完全可算 |
| **10** | **辙口只挑最顺的** | 全曲只用最宽的辙（言前、江阳一类），从不碰窄辙 | ✅ 辙口分布统计 |
| **11** | **押韵永远选第一个想到的字** | 韵脚全是最高频那批（爱/来/开/在）；没有一处"意料之外但成立"的押 | ✅ 韵脚词频 |
| **12** | **副歌各遍全同，且末遍既没改一字也没加尾** | 见下注 | ✅ 文本 diff |

> ⚠️ **第 12 条的例外**：**副歌各遍逐字全同在真实语料里占 27%，不是病**；
> 前两遍相同正是听众记住 Hook 的方式。**真正的问题只有一种：末遍既没改一个字、也没加尾**——
> 那叫全曲没有任何位置被点亮。**别去重写副歌，改末遍一到三个字即可。**

### 1.1 英文套话清单（命中即标）

```
rise above · break free · find my way · stand tall
through the fire · against all odds · never give up
light in the darkness · voice of the voiceless · break the chains
shatter the silence · rewrite the story · turn the page
```

**中文对应**：梦想、远方、光芒、翅膀、绽放、星辰大海、岁月静好、不负韶华。

### 1.2 ★ 三条最致命的

**不是因为最难查，而是因为它们读起来都不"错"：**

| # | 为什么致命 |
|---|---|
| **1（名词全抽象）** | ★ **最直接的 AI 指纹**。"时光""远方""梦""自由"——**每个都对，合起来是空的** |
| **2（对称到死）** | 四段每段四句、每句七字、句句押韵。**技术上完美，听感上是表格** |
| **3（什么都解决了）** | AI 会把情绪走完整：难过→释怀→祝福。**真人写词经常停在难受里** |

## 2. 四个一分钟粗筛（不用脚本）

1. **抽象词命中数 / 具体名词数** —— 抽象词多于具体名词，直接判危
2. **每段字数方差** —— 方差为 0 或极小 = 表格
3. **副歌各遍文本 diff** —— ★ 只看**末遍有没有改动**；前两遍相同不算问题
4. **韵脚字的词频排名** —— 全是最高频那批 = 选了第一个想到的

## 3. ★ 十二条全过了，还是像 AI

**这是本文件存在的主要理由。**

### 3.1 四个征兆

| 征兆 | 说明 |
|---|---|
| 主题句念出来**像主题词不像人话** | 它是个标签，不是一句话 |
| **贯穿道具说不出颜色和新旧** | ★ 说明它是**倒推出来的**，不是从记忆里拿的 |
| 具体名词有了，但**不构成系统**（随机堆意象） | 见 `imagery-system.md` |
| 不对称做了，但**那些不对称没有理由** | ★ **为了破坏而破坏，和整齐一样机械** |

### 3.2 一个更狠的测试

> ★ **把这首词的标题和所有专有名词去掉，给一个不知情的人看。**
> **他能说出这首歌在讲哪一件具体的事吗？**
>
> 说不出来 → 主题没有落到词里，**它只活在交付说明上**。

## 4. 整改路径

```
读着像 AI
 └─ ① 逐条过 §1 的十二条，数出旗标数
 └─ ② 旗标 ≥ 3 → 按下表逐个改
 └─ ③ 旗标 ≤ 2 但仍然像 → §3 的四个征兆
 └─ ④ 还是不行 → ★ 回「道具锚定」重做一遍，不要在词面上修
```

| 症状 | 先查 |
|---|---|
| 空、泛、什么都没说 | 道具锚定（多半是"这一件事"不成立） |
| 名词都是概念 | `imagery-system.md` |
| 整齐得像表格 | 段内字数方差 + 句子长短的稳定与不稳定 |
| 押韵顺但没意思 | 韵的意外度（见 `rhyme-zh.md` 选韵决策表） |
| 唱出来听成别的字 | `tone-check.md` |
| 不知道谁在说话 | 视角与时刻（见 `SKILL.md` 动笔前自查） |
| 情绪走完整了，没余味 | 留白：**至少留一条线不收** |

## 5. 交稿前清单

- [ ] **逐条**过了 §1 十二条，**数出了旗标数**（不是凭印象）
- [ ] 中文且**有旋律**时，跑过倒字检查并人工确认过高风险处
- [ ] ★ 做过 §3.2 那个测试：**去掉标题和专名，别人能说出讲的是哪件事**
- [ ] 每一处不对称**说得出理由**
- [ ] 具体名词**构成一个系统**，不是随机堆的
- [ ] 副歌末遍**确实不同**，且改动**有意义**（不是换个近义词）
- [ ] 抽象词与套话清单**零命中**
- [ ] 如果全过了还是觉得像 AI → **回「道具锚定」重做**，不要在词面上修
