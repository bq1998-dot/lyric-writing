# 歌词创作与歌词分析（五模式）

## 用户画像（跨模式通用约定）

以下几条五个模式通用，与下文规则互为印证：

- **语言跟着参照对象走** —— 参照的歌手 / 乐队有母语就取它的母语，不要默认"中文用户就走中文"。
  判据是"词在这个风格里承担什么功能"：硬摇滚 / 朋克 / 说唱 / 电舞这类"词＝乐器"的**英文优先**。
- **关键信息缺失就一次问清** —— 只问决定性的变量（语言 / 主题 / 参照对象这类，
  不问就整篇走偏的），**一次列完再等回答**，不许逐个挤牙膏；能推断的就别问，
  推断项在交付自检里标明。
- **交付纯段落标签版** —— 元标签一律移除，只留 `[Verse 1]` `[Bridge]` 这类段落名；
  同时给 `.md`（含创作说明 / 改动清单）与 `.txt`（可直接复制）双份。
- **风格与歌词严格分框** —— Style 框只放风格，Lyrics 框只放演唱文本；描述性词进歌词框会被唱出来。
- **韵部是第一杠杆** —— 要"换个方向"时顺序是：先换韵部音色 → 再换能量方向 → 最后才是曲风。
  同一歌手连写两首、曲风被锁死时，唯一真杠杆就是韵部。
- **造现场，不讲道理** —— 命题式主题先定一件"贯穿道具"，定义它在 4 个位置的状态变化，
  这变化本身就是曲式结构。验收＝逐段自问"这一段能不能拍出来"。
- **改稿时用户给的是"症状"不是"处方"** —— "意境差了意思""不到位"这类短语要自己诊断到根因，
  不要回头去问他要改哪里。
- **数字与风险一律跑脚本** —— 上声连用 / 字数 / 韵脚孤儿 / 时态漂移 / 实词自押，全部脚本统计，肉眼必漏。
  ★ **2026-09-20 补三条工程纪律**（都对应真实事故）：
  ① **调串不许手写** —— 先建「汉字 → Jyutping」字音表，**调串由程序生成**，
     并保留 `len(正文) == len(调串)` 断言。手写调串会写短/写错、产生假报警，
     **错的脚本比没有脚本更危险**（上一稿就因调串短两位虚报过问题）。
  ② **段长计数与复押计数是两套，不能共用一份列表** —— 重复段（副歌唱两遍）
     在段长检查里要**分别列出**（`C` / `C2`，各自 4 行合规），
     在复押检查里要**折叠成一遍**（共享 fold id，不重复计）。
     真实事故：脚本只列了一遍 Chorus，**词数少算 38 字**，报了个假的"偏短"。
  ③ **交付文本要回比校验稿** —— 脚本读**交付目录里的 `.txt`**，与校验用的歌词列表**逐行 `==` 比对**。
     曾靠这一步发现第二遍副歌被插在了 Verse 2 之前（行数一致、顺序错位，肉眼扫不出来）。
  ④ **第三方注音库是「独立第二意见」，不是定音的替代品**（2026-09-20 首次补做）——
     本机 `pycantonese` 可用：`pycantonese.characters_to_jyutping('秋風')` → `[('秋風', 'cau1 fung1')]`，
     **逐字传入即可取单字读音**。流程＝**人工按语境定音 → 库逐字 diff → 人工裁决分歧**；
     裁决后**必须检查分歧字是否落在承重位**（韵脚 / 声调敏感位）——不落承重位就不影响结论。
     **它的两个盲区**（实测踩到）：**验不了上下文多音字**——「著」只给 `zyu3`（著作）/`zoek3`（著衫），
     **缺**「吹著・憑著」要的 `zoek6`；「間」把「一間屋」标成「閒」的 `haan4`；
     **也不覆盖口语变调**。它验的是"单字音准"，语境定音永远得人来。
     **写这类脚本的两个坑**：① 别拿**全拼比韵母**（表里存 `jat`、库返回 `at`，直接比会整表误报）；
     ② 静默导入"会调 `sys.stdout.reconfigure()`"的模块时 `io.StringIO` 会抛 `AttributeError`，
     给它子类补个空的 `reconfigure()` 即可。
  ⑤ **★ 已固化为通用脚本，不要再每首新写**（2026-09-20）——
     `python scripts/verify_yue.py 歌词.txt` 一次跑完下列 9 项，退出码 0（全过）/ 1（有 FAIL）：
     ① 逐行字数与段内极差（含"呼吸点"判定）② 韵脚韵部/声调（入声 FAIL、升调 WARN）
     ③ 上声连用/三连 ④ 韵脚复押（按行文本自动折叠重复段，不需要手工 fold id）
     ⑤ 焦点字渗透 ⑥ 粤语特征字 ⑦ 段长上限 ⑧ 人味三指标 ⑨ 交付文本回比（`--compare`）。
     常用参数：`--focus 秋`（焦点字，可多次）｜`--genre ballad --bpm 78`
     （段长上限，**BPM < 80 时主歌上限自动收紧到 4**）｜`--compare 另一份.txt`（交付文本回比）。
     底层注音在 `scripts/jyut.py`。
     ★ **词→旋律侧用 `scripts/melody_fill.py`（2026-09-21 新增，第五个脚本）** ——
     `python scripts/melody_fill.py song.json out/ 曲名`，一次出 **简谱 + 倒字检查 json + `.mid` + `.wav`**。
     音符只写 `(级数, 八度, 时值, 起拍)`，**音节从歌词逐字自动绑定**（绑定不上直接报错）；
     含多音字/轻声覆盖表（`为`=wéi(阳平)、`得`=de(轻声)），**不定音会判错**。
     MIDI 纯手写，**不依赖 `mido`**。完整用法与五条判据见「模式 E」。
     ★ **普通话侧用 `scripts/verify_zh.py`（2026-09-21 新增）**：
     `python scripts/verify_zh.py 歌词.txt [--focus 说] [--genre ballad --bpm 78] [--compare 交付版.txt]`，
     **九项口径与粤语脚本逐项对齐**（底层 `pypinyin`，取 `Style.FINALS_TONE3` 拿韵母+声调）。
     两个脚本共同的判据：**空格不隔断相邻性**（`clean()` 先去掉全角/半角空白，再查上声连用）。
     **两个必须记住的坑**：
     · **入声不能用 `tone >= 7` 判** —— Jyutping 是**六调制**（1–6），根本没有 7/8/9，
       入声只靠**韵尾 -p / -t / -k** 判。老脚本里 `if t >= 7: mark = "入"`
       是一行**从不触发的死代码**（所以它从没报过入声韵脚）。
     · **简体字必须先转繁再注音** —— 简体字会命中"另一个同形字"的读音：
       「听」库直读 `jan5`（那是另一个字），正字「聽」才是 `ting3`；
       「松」直读 `cung4`（松树）而「鬆」是 `sung1`。**这类错误不报缺字、静默发生**，
       只能靠显式 S2T 表挡住。表内 338 条，缺字会列出来，补进去即可。
     两个体检命令：`--check-table` 查表健康度（目标字库认不认）；
     引擎的 `audit_necessity()` 列出"库本来能读、却被映射改掉"的字——**这批必须人工确认**
     （就靠它抓到过我自己写反的两条：「表→錶」「累→纍」，把对的音改成了错的）。
- **★ 三项可量化的「人味指标」**（2026-09-20 由「六首 90 年代经典 vs 自写三首」对照得出）
  ——交付前脚本跑，达不到就改。**这三项全是自写词系统性偏离经典的地方**：
  ① **第二人称计数** —— **"你" 不得为 0**（除非能明确回答"这首歌为什么不能有第二个人"）。
     实测六首经典 **5/6 首的"你"多于或接近"我"**（風繼續吹 我8/你13、追 我4/你10、
     一生中最愛 我6/你9）；自写三首 **"你" 全为 0**。
     没有"你"就没有**关系**，只剩**处境**——这是"正确但不感人"的根子。
     ★ **落地必查：「你」是阳上 5** —— 它出现在任何阴上(2)/阳上(5)字前面都会撞成上声连用。
     实测《同一陣風（第二版）》「你」出现 10 次，**每一次都要查左右两边的字**：
     拦下 `你只`(5+2)，落笔时避掉 `你走`(5+2)、`我也`(5+5)、`把你`(2+5)。
     常用替换：`你走`→`你離開`、`我也`→`我卻`、`把你的`→`記住你的`。
     ★ **必答问题：某段为什么没有"你"？** 允许局部无第二人称，但**必须有主题理由**
     （例：《同一陣風》Bridge 是"两者之间的桥"，桥不留人；Outro 必须落回"看"本身）。
     **"漏写"和"设计"的差别，就是能不能一句话说清理由。**
  ② **顿数分布（行内自然停顿数）** —— 同一首歌内**至少出现 2 行 3 顿或 4 顿**。
     实测《我行得夠》《不等天晴》是 **100% 两顿**（30/30、27/27），一行都没破过；
     经典 4/6 首大量用 3 顿（《似是故人來》18 行全 3 顿，《追》11/16 行 ≥3 顿）。
     3 顿＝"让步／转折／落点"，是最省力的破法。
  ③ **单行字数极差 ≥ 4** —— 主动安排一个 **≥12 字的满行**，后接一个短行。
     ★ **判据是"相邻两行字数差 ≥4"**（长句在前、短句在后），不是死抠"必须 ≤6 字"——
     11 字紧挨 21 字同样成立。能到 6 字以内最好，但那不是门槛。
     实测《風繼續吹》极差 **10**（11 字行紧挨 21 字行），《不等天晴》极差 **1**（27 行全 8–9 字）。
     **短句是被长句"喂"出来的**；全篇等比，就没有一个字是重的。
     ⚠️ **本条与第 4 项自检「段内字数差 ≤2」直接冲突，必须按下述口径调和**（2026-09-20 首次落地）：
     **把"整齐"拆成「主体」与「呼吸点」——**
     ① **主体行照旧守 ≤2**（同一段内，除呼吸点之外的相邻行）；
     ② 全曲必须存在 **≥1 处相邻行长差 ≥4 的呼吸点**，且**长句在前、短句在后**；
     ③ **呼吸点必须在交付文档里点名**（写清位置 + 理由）——
        **不许事后拿"这是呼吸点"给任何不整齐洗地。**
     落地例：《同一陣風（第二版）》副歌 `開過幾扇窗／換過幾個冬／沒你的影蹤`（15 字 · 3 顿）
     → 紧接 Hook `四季吹著同一陣風`（8 字），差 7；其余各段极差 V1 1 / V2 2 / B 2 / O 0。
  ★ **判据是"不要每一项都落在同一个值上"，不是把这些数字当成新的模板。**
- **风格提示词只补不改** —— 用户给的 Style 本身就是成品，动作是补漏（锁语言 / 锁不飙 / 防念白 / 速度锚），
  改完对原版要素逐条断言保留。

## 核心原则：缺关键信息就一次问清

用户的**创作**工作流只有两种，两种都先看输入够不够：

| | 模式 A · 器乐已定 | 模式 B · 只有想法 |
|---|---|---|
| 用户手里有什么 | 风格提示词 + 已经跑好的器乐 | 一个主题、一个意境 |
| 唯一变量 | 语言（中文 / 英文） | 无 |
| 要做的 | 直接填词 | 先提案，再直接写完 |
| 要不要问 | 语言没给就问一句 | 主题与意境已够，**一般不必问** |

**问的规矩（三条）**：

1. **只问决定性的变量** —— 不问就整篇走偏的才问：语言（普通话 / 粤语 / 英文，选错等于重写）、
   主题方向、参照对象。**细节不问**（歌名、字数、某个词怎么措辞这类，自己定）。
2. **一次问完，不许逐个挤牙膏** —— 把要问的一次列清再等回答；不要"先问语言 → 再问主题 →
   再问参照"这样来回。问完这一轮就动笔。
3. **能推断的就别问** —— 能从风格提示词、参照对象、语境推出来的，自己推，并在交付自检里
   标明哪几项是推断的。**问是为了不跑偏，不是为了把决策成本丢回用户。**

用户贴来**现成歌词**要诊断时，走 **模式 C · 分析已有歌词**（见下文）。
用户**已经有一份词稿**（自己写的、或是别的语言写的）要求改写并优化时，走
**模式 D · 词稿改写**（见下文）——与 C 的区别：**C 只诊断不改，D 要交出改好的成品**。

## 模式 A · 器乐已定，只缺歌词

### 输入
- 风格提示词（必给，用户会粘贴）
- 语言：**普通话 / 粤语 / 英文**（必给）—— 见下方「语言分支」
- 主题方向、歌名（可能没有 → 自己推导 / 提 3 个候选）
- **可选**：参照的音乐人 / 乐队（决定词的风格与语言层级），或**要"借意"的外部作品**
  （主题取自某部电影 / 小说 / 事件，但被要求不出现其人物 / 情节 / 标题）
  —— 见下方「借意：怎么取主旨不取情节」

### 语言分支（决定用哪套押韵体系）

| 语言 | 韵脚参考 | 关键约束 |
|---|---|---|
| 普通话 | `references/rhyme-zh.md`（十三辙） | 4 声调；上声（3）难拖长音 |
| **粤语** | `references/rhyme-yue.md`（粤语韵部） | **九声六调；入声不可拖长；必须协音** |
| 英文 | 无参考表 | 靠重音节与近韵，不靠韵脚 |

**粤语绝不能套普通话十三辙**——两套韵母系统完全独立，用错等于没押韵。
反向也成立：**普通话不能套粤语韵部**。两者互不干扰（粤语 `ou` 与普通话**由求辙 ou**
字族、音色都不同，不算撞韵），但**同一语言内部要防撞**——普通话十三辙之间互相会撞
（连写多首还要维护谱系表，见模式 B 第二步）。
粤语填词比普通话多两道硬约束：

1. **入声避坑**：-p / -t / -k 收尾的字（一 jat1、月 jyut6、不 bat1）短促，
   **绝不可作韵脚、绝不可落长音拖尾**。
2. **协音（melodic contour matching）**：字的声调走向必须匹配旋律走向，
   否则唱出来会**变成另一个字**——这不是"难听"的程度问题，是语义直接跑偏。
   没有旋律时按近似处理（句内声调有起伏、韵脚落平声、分词节奏规整），
   并在交付时**明确提醒拿到旋律后必须复核协音**。
3. **上声可作韵脚，但不可落在长音上**（2026-09-20 据六首经典实测修正）——
   原规则"阴上（35 升调）忌作长音韵脚"**是从普通话"上声难拖长"直接搬过来的，对粤语过度执行了**。
   实测六首经典（譚詠麟／張國榮／梅艷芳）的**韵脚位上声占比 6%–47%**：
   - 《愛在深秋》**8/17**（手·手·手·朽·走·我·你·你）
   - 《一生中最愛》**7/11**（海·起·己·己·己·你·你）——**阴上 35 连用四次，是谭咏麟的名曲**
   - 《風繼續吹》5/13、《似是故人來》6/18、《追》1/16
   正确约束是 **「上声不能落在需要拖长的长音上」，不是"不能做韵脚"**：
   阴上 / 阳上适合落在**短促的、下行的句尾**；平声（1/3/4/6）适合长音收束。
   ⚠️ 行末字 ≠ 必然的长音落点，**要确证仍需简谱**。

另外，粤语歌词**适度使用粤语特征字**能帮助演唱引擎识别为粤语而非普通话。
但全曲 2–4 处即可——通篇"唔啲咗"会掉档，80 年代港乐本身是文白夹杂的。

★ **但主流情歌本来就是 0 处**（2026-09-20 实测，重要）：林敏驄／鄭國江／向雪懷／林夕 写的
《愛在深秋》《風繼續吹》《一生中最愛》《追》《似是故人來》，**粤语特征字全部 0 处**——
90 年代主流粤语情歌的原生形态就是**粤语发音的书面语**（"無需為我假意挽留""未許它向下垂"）。
所以「2–4 处」**不是硬指标**：**面向内地传播时取 0 处，是贴合经典形态的选择，不是妥协**。
（反向警示：自写《我行得夠》用了 16 处，对照这六首**才是异类**。）

⚠️ **统计口径的坑**（2026-09-12 修正）：只计**字形上就能辨识是粤语**的专用字——
唔 / 嘅 / 咗 / 係 / 冇 / 咁 / 喺 / 佢 / 哋 / 睇 / 嘢 / 俾。
**「都」「點」不可计入**：它们的字形与通用中文完全重合（普通话同样在用"都""点"），
计进去必然误判——**这类误判会把"达标"的稿子报成"严重超标"，白改一轮。**

**语言层级由参照风格决定，不是"粤语就都写口语"**（2026-09-12 新增）——
上面 2–4 处是通用区间，真正的配额要看参照的是什么风格：

| 参照风格 | 语言层级 | 特征字配额 |
|---|---|---|
| 1980s–90s 港式文艺 / 另类向（synth-pop、post-punk、乐队组合一派） | **书面粤语、文白夹杂** | **2–3 处**，只放转折句或收尾句 |
| 市井流行 / 通俗情歌 / 网络热歌 | 口语粤语 | 4–6 处 |

原因：文艺向的词靠书面语撑冷感与距离感，口语虚词一多就塌成口水歌——
**不只是数量超标，是风格直接跑偏**；反过来写市井歌却通篇书面，会假。
判据：先把参照风格的"语言质感"写进风格解析表，再据此决定特征字配额。
⚠️ **最容易超配额的位置是 Pre-Chorus 与 Bridge**——那里情绪最外露，写起来会自动
滑向口语虚词（「做到冇咗…」这一类）。**定稿前必须按段点名去数，别只看全曲总数。**

### 语言怎么选（2026-09-12 新增）

用户给了参照风格、又在中文 / 英文之间权衡时，**判据不是"用户平时写什么"，
而是这个风格里"词"承担什么功能**：

| 风格类型 | 词的功能 | 语言选择 |
|---|---|---|
| 硬摇滚 / 朋克 / 说唱 / 电子舞曲 | **词＝乐器的一部分**：短、重复、当打击乐用 | **英文优先** |
| 抒情 / 民谣 / 叙事 / 城市流行 / 港式另类 | 词承载情绪与故事 | 用户母语优先（中文 / 粤语） |

理由：前一类风格靠**节奏与口气**取胜，词义让位于音感——英文的重音节奏、连读吞音天然贴合；
中文一字一音节 + 四声，要先把声调丢掉才能"甩"出去，结果常是
**"中文歌配了个硬摇滚伴奏"，而不是那个风格本身**。反之后一类风格里，中文的语义密度是优势。

**判据一句话**：如果这首歌把副歌让给了器乐（提示词里出现 `explosive instrumental choruses`
这类描述），人声只剩"喊"这一个功能——**喊是英文的母语场景**。

要写中文也不是不行，但**策略必须换**：放弃模仿参照风格的语感，改走中文同类风格自己的路
（如中文硬摇滚走史诗 / 愤怒，不是 AC/DC 的痞）。**那会是一首好歌，但不会是一首"中文 XX"。**
交付时把这条讲清楚，再附一句"要中文版说一声"。

### 英文的整齐度看重音节，不看音节数

英文弱读音节可压缩吞掉，**音节数不齐是常态**——同一段主歌的音节数可以是 7/6/5/9
（极差 4），而重音节是 4/4/4/5（极差 1）。**决定能不能唱的是重音节。**
自检第 4 项在英文下按重音节判，并把音节极差作为参考值一并报出，避免看起来"没检查"。

### 参照风格可以凌驾通用规则

通用规则写"全 perfect 押韵像儿歌"，但 AC/DC 的主歌**就是**四行同韵一口气砸完
（`Back in Black` 全押 /æk/）——那是 riff 的人声化，是风格特征而非缺陷。
判断顺序：**参照风格 > 通用规则**（与「语言层级由参照风格决定」同一逻辑），
但要在自检里写明"刻意违反 + 理由是 X"，不能默默破例。

### 流程（三步，严格按序）

**第一步 · 风格解析表**（必须先出，后续所有决策从这张表推导）

| 项目 | 读到的内容 |
|---|---|
| 曲风 / 子风格 | |
| 速度 | |
| 调性 / 和声色彩 | |
| 情绪基调 | |
| 动态走向 | |
| 人声设定 | |
| 乐器与编制 | |
| 制作质感 | |

- 未明写速度时按曲风推断并说明依据（trap ≈130–150 BPM；钢琴 ballad ≈65–80；
  city pop ≈100–115）。
- 提示词里描述动态走向的句子（"begins as a whisper… builds… strips back"）
  原文摘出——它是安排段落能量与配唱方向的依据。
- 读不出的格子写"未提供，按 X 处理"，不要瞎猜着填。

**第二步 · 推算音节密度**（决定歌词能不能唱得下）

| 速度 | 中文每行字数 | 英文每行重音节 |
|---|---|---|
| < 80 BPM | 8–12 字 | 6–8 |
| 80–110 | 7–10 字 | 6–9 |
| 110–130 | 6–9 字 | 5–8 |
| > 130 | 5–8 字 | 4–7 |
| 说唱 | 每 4 拍 10–16 字 | 每 4 拍 8–14 |

微调：`laid-back / lazy / 慵懒` → 取下限、句尾留白；`driving / punchy / 推进`
→ 取上限、重音前移；`sparse / minimal / 留白` → 允许句间空拍，用破折号标记。
副歌每行字数应明显短于主歌，重复率明显高于主歌。

**第三步 · 写词** → 规则见下方「写词规则」。

### 输出格式（四项）
1. 风格解析表
2. 韵脚板（韵母 / 字族 ≥12 字按声调分组 / 韵式 / 每段计划字数）
3. 完整歌词（带段落标签 + 演唱方向标注）
4. 交付自检（13 项，逐条给结论）

### 硬性禁令
- 不提问。
- 不修改、补全或重新设计风格提示词——它是既定条件，不是讨论对象。
- 不输出曲风建议、混音建议、发行建议。

### 借意：怎么取主旨不取情节（2026-09-12 新增）

用户给一部作品（电影 / 小说 / 剧）说"取它的中心思想，但不许出现人物、情节、标题"时，
走**降两级抽象**：把作品拆成三层，只留最底一层。

| 层级 | 内容 | 处理 |
|---|---|---|
| ① 专名层 | 人名 / 作品名 / 地名 / 标志物名 | **全部剔除**，一个不用 |
| ② 情节层 | 发生过什么事件 | **全部剔除**，全曲不以事件推进 |
| ③ 命题层 | 中心思想（通常 3–5 条） | **全部保留**，逐条指定落点段落 |

流程：
1. 先把命题层**逐条写出来**（例：希望是别人抢不走的 / 自由是挣来的，不是被给的 /
   真正锁住人的是习惯不是石头 / 有人出去后反而活不下去）。写不出 3 条以上，
   说明这部作品的"意"还没抓准，**别动笔**。
2. 每条命题**指定一个落点段落**（副歌表态 / Bridge 点破 / 主歌反向论证）——
   歌词就有了骨架，且全程不需要任何情节。
3. 全部意象**泛化到可替换**：写「牆 / 石頭 / 刻痕 / 枷 / 路 / 圖」这类通用意象，
   不写任何具体物名。
4. 交付时**逐词扫一遍指向性清单**（专名 + 情节动词 + 标志物），确认 0 命中。
   验收线一句话：**全篇无一处可反查回那部作品**。

配套的选韵诀窍：**先看题目的题眼字落在哪个韵部，韵部自己会说话**。
写"囚禁与脱出"选 **ou**——「牢」lou4 与「逃」tou4 同属一韵，囚与脱只差一个声母，
**韵部结构本身就是主题结构**，不必为押韵硬凑字。这比"按情绪挑韵部"更进一层。
Bridge 换韵同样能做成内容：主韵是圆唇闭合音（ou）时，Bridge 换最张口的韵（aa），
**口型从闭到张＝从内到外的物理动作**。

### 器乐提示词的演唱版改写（2026-09-12 新增）

用户给的风格提示词常常是**器乐版**（给视频/纯音乐用的），里面藏着「别唱」开关。
要拿去生成演唱版时**不是删两句就行**——逐处过一遍下表：

| 常见片段 | 处理 | 理由 |
|---|---|---|
| `instrumental only` / `instrumental` | **删** | "只出器乐"的主开关，不删绝不开口 |
| `no vocals` / `without vocals` | **删** | 与上重复 |
| `no spoken words` / `no spoken word` | **保留** ⚠️ | 它防的是念白段，与"唱不唱"无关；连带删掉容易冒出一段 spoken word |
| `leave deliberate vocal space in the midrange`（及同类"预留空间"句） | **改写** | 器乐版是"预留"，人声版要"占住" → `lead vocal dry and forward in the midrange` |
| `clear N-bar intro` / `instrumental turnaround` / `instrumental break` | **保留** | 器乐段在人声版里依然存在，是编曲的呼吸点 |

删掉的位置腾出来填**人声描述六类**，缺任何一类都容易出问题：

1. **语言锁定** —— `Cantonese male lead vocal, sung in Cantonese` / `Mandarin male vocal`。
   最要紧的一条，防口音漂移。
2. **声线** —— 由参照风格决定，且**必须写对**。仿达明一派 / 黄耀明那一路是
   `high-placed male tenor with a soft nasal edge`（偏高、带鼻腔共鸣），**不是低音炮**；
   声线写错，整首气质就散。反之仿低吟民谣则是完全相反的方向。
3. **唱法** —— `cold and detached, deadpan conversational, never belts or oversings`。
   文艺 / 另类向必须写死"不喊不飙"，否则副歌会被拉成流行大歌。
4. **气息** —— `breathy, intimate, restrained vibrato`
5. **混音位** —— `dry and forward in the midrange`
6. **和声** —— `sparse cold backing harmonies on choruses`

**给长短两版**：完整版（保留原提示词的全部制作细节）+ 精简版（砍掉制作形容词、
留人声与编曲骨架）。**V6 的 Style 框上限 1000 字符**（V4.5–V5.5 同为此值）。注意
**V5 及更早的全部模型已于 2026-09-09 随 V6 发布下线**，模型选择器里已经选不到——
任何针对旧版（"V5 的 Style 框约 950 字符"这类）的参数与行为描述都已失效，
不要拿旧版经验做对比实验。两版都备着最省事。**字符数要用脚本数，不要目测**（与字数同理）。

**歌词侧配合**：可加 `[Breathy]`（气息段）/ `[Harmonies]`（副歌和声垫底），
但**绝不能加 `[Emotional Climax]` / `[Belted]` / `[Explosive]`**——与"不喊"的设定直接冲突。

## 模式 B · 只有一个想法

### 输入
主题 / 想法 + 意境 / 氛围（可能只有一两句话）

**语言未指定时自己推断，不要问**：会话里已有作品 → 沿用其语言；用户在粤语/普通话场景下
持续对话 → 沿用；真无上下文才默认普通话，并在自检第 13 项把"语言系推断"标出来。

### 参照歌手 / 乐队，但没给风格提示词（2026-09-12 新增）

用户说"来一首 XXX 风格的歌"、甚至贴了一段唱将分析，却**不给可粘贴的提示词**时，
这**仍走模式 B**（主题、韵部、曲风三样都由你定），只是多出两件必做的事：

1. **先出一张「特质 → 提示词落点」对照表**：把分析里每条声音特征翻译成英文提示词片段，
   并写出**反面**（写错会变成谁）。这张表是交付的核心价值——用户给的是中文听感描述，
   能落成提示词才算真的接住。
2. **语言直接取参照者的母语**（参照普通话歌手 → 普通话；参照粤语歌手 → 粤语），不要问。

判断"能不能被提示词抓住"，看的是**声线形状 + 语感 + 动态约束**三样，**不是音域数字**。
最通用的四件套：`音色（smoky husky female alto）`+`声区（deep chest-voice register）`
+`语感（conversational storytelling phrasing）`+`动态（never belts or oversings）`，
再加一个语感开关 `sits slightly behind the beat`。
**分析里写着"高音偏闷 / 不够明亮"的，靠"不写 `bright`、不写 `higher`"来实现**——
负面特征只能用**不写对手词**来达成，直接写 `not bright` 引擎基本吃不到。

### 同题续作：换体裁，不换字（2026-09-18 新增）

用户隔一天给出**几乎同一个主题**、只把曲风换掉时，
**第一约束不是「写得好」，而是「不能是它的换字稿」。**

**动笔前必须有一步只读侦察：先查此前作品里有没有同题材前作。**
做法：在既有词稿库里按题材关键词检索（`漫步` / `愿` / `时光` / `分离` …），
查到了就**把它当既定条件完整读一遍**（体裁、速度、结构、落音、道具全都要读出来）。
漏掉这一步的代价是写出姊妹篇，而用户未必会明说"这个题材我写过了"。

★★ **侦察动作 2026-09-20 收紧——「列出文件清单」不算侦察，会漏。** 必须做三件事：

| # | 动作 | 为什么 |
|---|---|---|
| **1** | **拿"你打算用的 Hook 词 + 核心意象短语"去 grep 全库正文** | 清单只能看出"写过同题材"，看不出"写过同一句话"。2026-09-20 写粤语稿时，前一版与 8 天前的《還給從前》在**主韵阵容（in+oi）、Hook 短语（对方 V2 有「堵在唇邊」，我准备用「話到唇邊」）、道具类型（旧物承载未说的话）**上三样同时撞车——**列文件清单完全看不出来，grep 关键词一眼就露**。定稿前必须重跑一次 grep。 |
| **2** | **做一张「作品 / 主韵 / Bridge 韵」阵容对照表，逐行比对** | 韵部阵容是**听感层**的姊妹篇来源：主韵撞、Bridge 也撞，两首并排就是一对。新稿的**主韵与 Bridge 必须至少有一项是全库首次**；若无法避开（用户指定），在交付文档里明写撞了哪一项、凭什么仍成立。 |
| **3** | **撞到先判严重度：默认重做，例外保留且必须披露** | 撞 Hook 短语＝撞结构；换掉一个词不解决。**默认路径＝整首重做**，顺序照旧：**先换韵部（音色）→ 再换 Hook 句式 → 再换道具**，重做后重跑 1、2 两步。<br>★ **例外路径（2026-09-21 新增）**：若撞的只有「主韵同部」一项，而**副歌骨架 / 落点态度 / 道具变化方式**三条都不同，可向用户说明重叠并给保留依据；用户裁定可接受时**保留成稿**，但必须**双向标注**——总览谱系表 inline 标注 + 作品文档专节披露（相似点表／保留依据／同专辑区隔方案）。<br>★ 判据：**「撞了」不等于「必须废」；但「保留」必须留下披露记录**——否则下次侦察会把「已知并接受」误读成「漏检」。**默认重做；例外保留，且必须写下来。** |

差异要在**体裁层面**成立，靠换近义词撑不住：

| 维度 | 动作 |
|---|---|
| 律动 / 曲风 | 换（同曲风 = 姊妹篇） |
| 结构 | 换（四段等长 VCVC ↔ 12 小节蓝调循环） |
| **贯穿道具** | **换**，且新道具应自带"会变"的属性 |
| **落音元音** | **重新推导**，不是沿用（见「英文」第 12 条：禁令可能不适用新体裁） |
| **主题的处理** | 换**态度**——这才是差异真正的来源 |

★ **体裁自带的态度差，就是差异的来源。** 同一个主题交给不同体裁，会自动长出一层新读法——
抒情民谣的天性是「愿此刻成真」，蓝调的天性是「好日子后面跟着坏消息」：
同样是"愿此刻停留"，前者的读法是**求**（不点破威胁），后者的读法是**怕**
（威胁明写，愿望变成跟时间讲价）。同一条素材在两边的落法也完全不同：
同一束阳光，一边是**光在水上**（纯景物），一边是**太阳是一个正在减少的存量**（倒计时）。

**验收一句话**：把两首歌词并排放，**除了主题相同，能不能一眼看出是两种体裁。**
看不出来，就还没写完。

**同题第三次解（同题 N 解）：约束从「不是换字稿」升级为「N 解必须 N 向」**（2026-09-18 晚新增）。
同一主题连写到第三首时，判据变成——**下面四条线里任何一条与前两首撞车，都会听成姊妹篇**：

| 线 | 三解怎么拉开 |
|---|---|
| **落音动作** | 亮（/eɪ/）→ 滑下去（/oʊ/）→ **挂住（/ɑr/）**，见「英文」第 9 条 ② |
| 结构 | 四段等长 VCVC → 12 小节循环 → **AABA 32 小节** |
| 贯穿道具 | 一件换成另一件，**新道具要自带"会变"的属性**（不能是同一件的近亲） |
| 主题态度 | 求 → 怕 → **认了还要求** |

★ **主题不变时，最后一个没被用过的变量是「说给谁听」。**
前两首若都是"对天说 / 对时间说"，第三首就把"讲价对象"在 Bridge 当场移交——
**改口对人说**。而 Bridge 通常是全曲唯一换韵处：**换韵＝换听众**，
韵脚换在哪儿本身就是结构信息。

⚠️ **配套纪律：方案表里的时长不能直接抄。** 真出过把"32 小节 @72 BPM"写成 ≈1:56 的
笔误（真值 1:47，1:56 对应 66 BPM）。**结构骨架可以沿用，但时长 / 词数 / 落点必须落笔时
重算**（算式：`小节数 × 60/BPM × 每小节拍数`；12/8 按附点四分＝BPM，每小节 4 拍）。

### 流程（三步，一口气做完，中途不停下等确认）

**第一步 · 提炼内核与素材**
1. 一句话内核——不是复述主题，是提炼。例：把"关于失去"提炼成"承认自己早就
   知道会失去，只是一直不肯说出口"。
2. 5–8 个可入词的原始素材：具体画面 / 物件 / 动作 / 时间 / 地点 / 声音 / 气味。
   格式 `素材 → 它承载的情绪`。抽象的一概不要。
3. 指明这个想法最适合的承载方式：靠副歌喊出来？靠主歌叙事？还是整首反复说
   同一句话？

**主题分三类，承载方式不同**：
- **事件类**（不愿分手、出发去远方）：有情节，靠主歌推进、Bridge 转向、副歌表态。
- **意境类**（迎风飞舞、孤独、被爱困住）：没有事件、没有人物冲突，**不能靠叙事推进**。
  解法：全曲用**同一类动作**串段（如「飘 / 飞 / 松手 / 张开 / 落到」），
  靠动作的递进代替情节；Bridge 才第一次停下来反问（"風停了我會怎樣"），答完立刻回副歌。
  另外——**意境类要先把"能量方向"定死**（升 or 沉），整首所有段落都服从它，
  这比选曲风重要得多。
- **命题类**（"人这一生 总有几次要转身""每个人都会…""我们终将…"）：主题句是一句**规律**，
  不是一件事。**最容易写成格言串烧**——每句都对，但整首没有一个人、没有一件东西。
  解法见下（**道具锚定**），这是三类里唯一必须"先找物、再写词"的。

**第二步 · 三套方案**（风格要拉得开，不是三个变体）
每套含：一句话定位 / 可直接粘贴的曲风提示词（曲风+情绪+乐器+人声+质感+BPM，
不写艺人名）/ 韵脚（普通话韵母 / **粤语韵部** / 英文韵式）/ 结构骨架 / 3 个歌名候选 /
1–2 句副歌 Hook 草句 / 适合场景。

**粤语走模式 B 时**：每套方案都必须写清主韵韵部与 Bridge 换韵部（读 `references/rhyme-yue.md`
的选韵决策表），并同样受入声禁忌与协音约束——模式 A 的粤语分支规则在这里全部适用。
**"改方向"的关键往往是换韵部，不是换曲风**：同一歌手两首都是 -ng 尾韵会听成姊妹篇，
换到 eoi / oi / oeng 这类不同音色的韵部才算真正换了方向。
**三个杠杆按顺序动**：① 韵部（音色暗 / 亮）→ ② 能量方向（全曲升 or 沉）→ ③ 曲风。
听众的第一直觉来自韵部音色，不是编曲。**同一歌手连写两首时，第 ③ 个杠杆直接失效**
（曲风由歌手锁定，改不动），可动的只剩韵部与能量方向——**这时韵部必须换到音色相反的方向**
才拉得开（例：上一首走**由求辙 ou/iu**（圆唇·回荡），下一首就得走
**人辰辙 en/in/un**（闭合·前鼻音）——音色正好相反，不会听成姊妹篇）。
若要连着写多首，建议维护一张
「作品 / 主韵 / Bridge 韵 / 能量方向 / 曲风」对照表，避免撞韵部阵容。
三套方案之后明确指出推荐哪套及理由（一两句，说清取舍）。

**第三步 · 直接写完** —— 按推荐方案出完整歌词，不等用户选。

### 输出格式（五项）
1. 内核与素材
2. 三套方案
3. 完整歌词（按推荐方案）
4. 交付自检（13 项）
5. 换方案方式（一句话：想换方案 B/C 该说什么）

### 硬性禁令
- **主题与意境已够动笔**——不要为了凑信息量反复追问；缺的细节自己定。
- 不给完三套方案就停——必须把推荐的那套写完。
- 不输出曲风科普、乐理教程、发行建议。

## 模式 C · 分析已有歌词

用户贴来现成歌词，要诊断 / 挑毛病 / 判断能不能用。**先诊断，不要急着改。**

### 流程（七步）

**1. 逐句抓韵脚。** 只取每句最后一个实词音节。轻声虚字（了 / 着 / 的 / 吗 / 吧）单独
标为「无韵」，不计入押韵位——但要记下来，句尾轻声 = 落点泄气，是要单独指出的问题。

**2. 归辙。** 先判语言再归辙：普通话对照 `references/rhyme-zh.md` 判十三辙归属，
**粤语对照 `references/rhyme-yue.md` 判粤语韵部**（粤语不能套十三辙）。
逐段列出辙口序列。
同段内连续同辙的句子合并计数，换辙处单独标出。

**3. 统计换辙次数。**

| 段内换辙次数 | 判定 |
|---|---|
| 1 | 优秀（段内统一） |
| 2 | 合格（主歌常见） |
| 3 | 偏散，建议处理 |
| ≥ 4 | 塌陷区，必须处理 |

Bridge 与 Outro 放宽一档——Bridge 是全书唯一允许转向处，Outro 允许散。

**4. 算声调风险。** 统计每个押韵位的声调（1 平 2 阳平 3 上声 4 去声），算**上声占比**：

| 上声占比 | 判定 |
|---|---|
| 0–20% | 安全 |
| 20–40% | 可接受 |
| > 40% | 危险——上声调值 214，拖长音易变调，AI 演唱尤其容易咬字变形 |

副歌核心落点必须单独看，不能只看全段平均。Hook 里若有反复出现的上声字
（如「自己」），明确标为生成风险点。

**5. 数字数。** 逐句数列，算段内极差：

| 段内极差 | 判定 |
|---|---|
| ≤ 2 | 合格（**主体标准**） |
| 3 | 偏大 |
| ≥ 5 | 节奏不稳，需重排 —— **除非它是一处"呼吸点"**（长句→短句、相邻差 ≥4，且已在交付文档点名） |

副歌若有「5+5」这类分句，按**每口气的字数**算，不按整行算——分句是加分项，要指出来。

**6. 查空洞句与滥意象。** 逐句问「这句能不能塞进任何一首别的歌」，能就标出；
对照禁用清单（梦想 / 远方 / 光芒 / 翅膀 / 绽放 / 星辰大海 / 岁月静好 / 不负韶华）。
**英文词另扫一道句式**：`no … no …` 排比否定（见「写词规则（创作模式共用）· 禁用句式」）。
**必须区分两种通用句**：位于情绪最高点的「旋律性通用句」反而利于跟唱，可保留（但注明）；
位于叙述位的通用句则必须换。

**7. 查演唱友好度。** 这一步纯靠"念出来"验，两类问题：

- **琐碎日常动作词** —— 若某句的核心意象落在「家务 / 日常动作清单」的项上
  （吃饭、洗碗、刷牙、赶车、叠衣服），而不是落在**物象**上（灯、窗、站牌、外套），
  标为 P2。抒情段落里放动作词会把情绪降维成生活流水账。
  改法口诀：**动作 → 物象**。「有人等我吃饭」→「那盏灯还没关」——
  同一层暖意，藏在物里不说破，既雅又好唱。
- **上声连用阻滞** —— 一句内相邻出现 2 个以上上声字（如「等我」「等你」），
  咬字会发紧、易连读成一团，标为 P0。这是上声占比之外的**独立**检查项：
  占比可能没过线，但局部连用照样难唱。

判断口诀：**把句子念三遍，念着别扭的地方就是病灶**，再去归因是声调、字数还是用词。

**8. 判能量弧线与段落推进。** 给每段打能量值（0–100），检查：低开高走的走向是否成立、
Bridge 是否承担了转向、主歌 2 是否带来新信息、**有无整段原样复制导致空转**。

### 输出（三块，缺一不可）

1. **总评表** —— 结构 / Hook / 韵脚 / 声调 / 用词 / 字数，六维打分 + 一句话结论。
2. **问题清单** —— 按 P0 / P1 / P2 分级，每条必须给**具体改法**（原句 → 建议句），
   不能只说「这里不好」：
   - **P0** 影响演唱：声调风险、上声连用阻滞、唱不下的长句、轻声落点
   - **P1** 韵脚结构：串辙、换辙过多、自押复押
   - **P2** 用词：滥意象、空洞句、琐碎日常动作词、语义模糊、句式重复、排比不齐
3. **亮点清单** —— 明确指出哪些地方**不要动**。只列问题会让人把好句子一起改掉。

### ★ 十二行拆解表（2026-09-20 新增，固定栏目不许换）

诊断必须用这张表：**立意 / 对谁说 / 时刻 / 贯穿物件 / 破题句 / 段落分工 / 视角 /
意象系统 / 语言层 / 不对称与留白 / 与曲的咬合 / 可迁移的一条**。

**三条纪律**：① **先整首过一遍再动笔**（边看边记会把结构记成句子）；
② **只写看得见的**（"他想表达孤独"不是观察，"全篇只有一个人称、没有'你'"才是）；
③ ★ **填不出来的格子不许空着，要写"这一栏没有"**——**"没有"是发现**。

★ **顺序是从中间填起**：先填 5–10（看得见的）→ 11 → 回头填 1–4 → 最后填 12。
**立意是拆出来的，不是看出来的**；先写立意，你会把印象写上去，再在下面找证据圆它。

外加一行必写：**学不来的部分**（有多少好处依赖这个歌手、这个时代、这段旋律——
记下来，但**不要当成方法**）。

**完整问法、改稿方向（从"景"移到"人"）见 `references/case-dissect.md`。**

### 可视化（有条件时用）

分析结果适合配两张图，比纯文字清楚得多：**韵脚辙口地图**（每段一行，色块宽 = 该辙
连续句数，直接暴露塌陷区）与**能量弧线**（双线：情感能量 + 上声占比，看两条线是否在
副歌同时冲高）。

### 硬性禁令

- **不整篇重写**。用户要的是诊断，改动按句给，让他自己判断。
- 不擅自给「换一首我帮你写」这类替代方案，除非用户明确要求。
- 打分要敢下判断。「整体不错，稍作调整」是无用结论。
- **亮点必须写**。只列问题是失败的分析。
- 分析完可问一句是否要按建议改，但不要未问先改。

## 模式 D · 词稿改写（跨语言 / 优化）

用户**已经有一份词稿**，要求改写成另一种语言（常见：普通话 → 粤语）并优化。
与模式 C 的关键区别：**C 只诊断，D 要交出改好的成品**。

### 第一原则：跨语言改词 ≠ 翻译

词稿能直译的只有**词汇层的一半**（灯 / 茶 / 雨天 / 门牌 / 车票 / 从前——意象全保留）；
**每一句的落点与声调都得按目标语言的语音系统重排**。原因：原词是**按源语言的声调写的**，
换语言唱会批量倒字。所以这不叫"翻译"，叫"**保留骨架与意象，重排落点与声调**"。

★ **可唱性优先级**（2026-09-20 新增）：跨语言 / 改编时，**意义 ＞ 措辞 ＞ 可唱节奏 ＞ 韵 ＞ 字面**。
**字面忠实是最低优先级**——为了字数整齐而牺牲意义是错的。
套既有旋律时：**近似保留音节数，把重音词放在强位**（与「戏仿 / 改编叠加规则」同一条）。

★★ **跨语言转换三条经验**（2026-09-21 新增，实测自粤语《話到唇邊》→ 国语版）：

**① 动笔前先做「源稿主韵 → 目标语言辙口」对照表——它决定工作量级。**
把源稿每个韵脚字拿到目标语言里注音、归辙：
- **整部落进同一个辙** → **结构可原样保住**，改动只在个别声调与用词。
  实测：粤语 **in** 韵 10 个字（边天前年变遍面现线见）**100% 落国语言前辙**、
  **oi** 韵 4 个字（开来袋爱）**100% 落国语怀来辙**——
  于是 26 行里 **25 行逐字对应（繁→简）、韵脚一字未换**。
- **散落多个辙** → 必须**重新选辙 + 重排落点**（等于重写韵脚板）。
（对照：多辙混用的稿子如《去看看世界》主歌遥条+人辰、副歌一七，必然走第二条路。）
**先算这张表，就知道接下来是"改几个字"还是"全篇重排"。**

**② 辙口可以整部保留，声调几乎全部重排——但"上声"必须整篇重扫。**
实测 14 个韵脚字里只有 3 个（边 / 天 / 开）源语言与目标语言恰好同调，其余 11 个调值全变。
★ 关键：**源语言的"升调"与国语的"上声"是两套系统、字表不同**——
源稿验过 0 处上声连用，**不代表国语也是 0**。最大新增风险源＝
**粤语入声字在国语里常变上声**：实测「笔」粤 **bat1（入声）→ 国 bǐ3（上声）**，
它在源稿里连"升调"都算不上。**转换后必须整篇重跑上声连用，不能沿用源稿结论。**
（同源风险：源语言的**轻声/入声**在目标语言里可能变成实调，需逐字查而不是整批推断。）

**③ 源语言那条"全平调韵脚"的结论不可搬。**
粤语"平调"涵盖 1/3/4/6 四调，国语"平声"只有阴平/阳平；同一批字在粤语是平调、在国语可能天然是去声
（实测：面 / 变 / 线 / 见 / 现 五字在粤语是平调、在国语是去声）。硬凑"全平调"就得换掉这些词，
那正是本条禁止的"**因改写丢掉原词的眼**"。
**改守目标语言自己的硬线**——国语侧是**零 3 声韵脚**（上声落长音会拐调，去声落长音完全正常）。

### 流程（四步）

**第一步 · 按"能不能唱"诊断原词**（复用模式 C 的检查，但聚焦三类致命项）

| 优先级 | 查什么 | 源语言 → 粤语时的典型症状 |
|---|---|---|
| **P0** | **倒字** | 源语言声调 ≠ 粤语声调。普通话的 3 声字（"软"ruǎn）到粤语可能是阳上（jyun5），旋律对不上。**不是修个别字，是全篇重排** |
| **P0** | **入声韵脚** | 普通话没有入声概念，写出的"告别 / 真切 / 熄灭"到粤语全是 -t / -p / -k 短促字，**绝不可作韵脚或落长音** |
| **P1** | **韵脚串辙** | 源语言的押韵不能平移。普通话的"你 / 期 / 里"在粤语里分别是 **ei / ei / eoi** 两个韵部 |

**第二步 · 重新选韵**（读 `references/rhyme-yue.md` 的选韵决策表）
选韵先看**意象群落在哪个韵部**：如果原词的意象全是**具象物象**
（灯 / 茶 / 雨天 / 门牌 / 车票 这一类），而粤语 **in 韵**（眠尖天前變年邊言遷）
正是物象密度最高的韵部之一，主歌用它就自洽。但副歌若要**直呼"你"**，
而"你"在 **ei 韵**——两段就必然换韵（见下）。

**第三步 · 逐句重写，守三条**（按 `rhyme-yue.md` 第八节"改词速查"的顺序动刀）

1. **原词的意象与情感逻辑尽量一字不动**——改的是落点、声调、语序，不是内容。
2. **每一句都跑脚本数字数**（不许目测），段内极差 ≤2。
3. **扫上声连用**：源语言的高频组合在粤语里常撞成阳上+阳上
   （"了你"liu5-nei5、"你偶"nei5-ngau5、"等你"dang2-nei5）。这类**只有逐字标调才查得出**。

**第四步 · 交付逐行改动清单**（D 模式的核心产物）
每行写：`位置 | 原词 | 改写 | 改动理由`。**理由必须落到具体语音依据**
（入声不能拖长 / 阳上连用 / 韵部不同 / 段内撞音），不能写"这样更好听"。
清单让用户能判断你动的是不是他想保留的地方。

### 输出格式（四项）
1. **原词诊断表**（P0 / P1 / P2，含证据）
2. 风格解析表 + 韵脚板
3. 完整歌词
4. **逐行改动清单** + 13 项交付自检

### 硬性禁令
- **不因改写丢掉原词的眼**——用户原稿里最好的那一句，结构必须原样保留，
  **只动必须动的那几个字**（例：一句收在"给了你"上的话，若"給了"是阳上+阳上连用，
  就只换这两个字，其余一字不动）。
- 不做"两种语言并列给用户挑"——用户已指定目标语言，直接改完。
- 改动清单里每一个"改"都要能追溯到语音理由，**没有理由的改动一律回退**。

### 按视角换韵：多韵部是设计，不是跑韵（2026-09-12 新增）

常规做法是一韵到底、Bridge 换韵再回来。但**当段落之间的"视角"发生变化时，
换韵部本身就是修辞**：

| 视角 | 选什么韵 | 粤语示例韵部 |
|---|---|---|
| **物象层**——写看见的东西（灯 / 茶 / 车票） | 具象字密度高的韵 | **in**（眠尖天前邊言） |
| **人称层**——直呼"你"、写关系 | 称呼字所在的韵 | **ei**（你期地） |
| **动作层**——写"放 / 开 / 交出去" | 开口、外走的韵 | **oi**（愛內開來） |

判据一句话：**不看"哪个韵好听"，看"这一段在做什么事"**。
段内必须严格统一（逐段脚本核验）；段间换韵＝换视角。交付时要把这条说明白，
否则会被人当成跑韵。

### 缩短：按功能删行，不按质量删（2026-09-13 新增）

用户说"缩短 / 太长了 / 唱不下"时，**不要按质量挑句子删**——一份被要求缩短的稿子，
通常是**没有弱句、只有太多好句**（长稿逐句都成立，所以才长）。
挑"最差的"删必然砍到用户喜欢的句子。正确做法：
**把段落拆成功能，一个功能只留一处表达。**

流程三步：
1. **给每段列出它必须承担的功能**（例：主歌＝物证 / 前副歌＝一句承诺 /
   副歌＝邀请 + 等待的证据 + 低音落点 + 身份 Hook）。
2. **同一功能在段内出现两次的，删其一**——删的时候留"更具体的那一处"。
3. **删完复核两件事**：① 时态 / 人称是否因删行而断裂；② 保留下来的功能是否还完整。
   若功能缺了，说明删错了对象。

**三类最常见的"功能重复"**（删的时候照这三类找）：
- **同一功能的两种问法**——"我怎么找到你"若前副歌已经用"每条路都通向你家"承担了，
  主歌里再写"我不需要地图 / 过了那片田"就是重复；
- **同一意象的两次出场**——副歌首尾都用"房子"（"让整屋都听见" ↔ "这些老墙"），
  同一个意象说两次，留一次；
- **把副歌的功能写进了主歌**——主歌在写"等待"，却插进四行"她有多好"；
  那是副歌的活，放在主歌里会**打断动作链**。


⚠️ **算缩减幅度时，原稿的重复段落必须一并计入**——原稿副歌若出现 **3 次**
（两段 `[Chorus]` + 一段 `[Final Chorus]`），只计 1 次会把缩减幅度误报成 −12%。
**段落重复次数是校验脚本最容易漏的参数**，另外"逐段行数"要数**行数**不是**段落数**。
两个错本轮都真实发生过。

**若用户另提"某段要压到 N 句"**（如用户要求「Verse 1 六句改四句，只压所有主歌」）：
先确认**范围**（只压主歌？还是含副歌？副歌一动低音落点设计就会散），再按
「结构（中英通用）」的"主歌段行数统一为 4 句"三条铁律执行——**成对删韵、锚句不动、复核主题**。
⚠️ **压句 = 改换气点**：删行加行直接改变后端的乐句边界，压完必须按新行数回读一遍
（每行末尾能换气），见「Suno 交付格式六条」第 1 条。

## 模式 E · 填旋律（词已定稿，用户要"出旋律稿"）

用户手里**已有定稿的词**，说"填旋律 / 出旋律稿 / 给这首词配曲 / 我想听它唱起来"。
与模式 A 的区别：**A 是曲已定只缺词；E 是词已定、反过来写曲。**
2026-09-21 首次落地（《话到唇边》国语版），产出的判据与纪律如下。

### 第一原则：先定"动作方向"，再挑音

★ **旋律的第一条线是"这句话在做什么动作"，第二条线才是好不好听。**

落地例（《话到唇边》）：「话到唇边」写成**下行四音 `1' 7 6 5`**——
「话」在最高点、「边」反而落低。因为整首歌的结论是**没说出口**；
**旋律若上行收尾，唱出来就是"说出去了"**。词曲最后是同一个动作。

**工序**：
1. 拿标题句 / Hook 句，写出它的**动作方向**（往上 / 往下 / 悬住 / 落下）；
2. 把动作方向翻译成**音级走向**（上行 / 下行 / 同音反复 / 前倚）；
3. 才去挑具体音高与节奏。
**倒过来做（先挑好听动机再往词上套）＝后面每个音都在给错的方向做装修。**

### 第二原则：空拍是倒字检查最省力的工具

**没有进入音程，就没有倒字。** 所以：

- **每段的起句、每个 Hook 的起字，优先用空拍进入**（简谱写 `0 1' …`）。
- 落地例：起字「话」是**去声**（最怕上行进入），三遍 Hook 之所以**零倒字**，
  唯一原因是前面留了 **1 拍空拍**。
- 这条比事后"换字"便宜得多——**换字要动词（词已定稿还动不了），空拍只动节奏。**

### 第三原则：倒字检查只看三类位置，不看总率

跑 `tone-check.md` 的口径（判「进入本字的音程」× 本字调型），
但**结论按 §4 的三类高发位置给**：

| 位置 | 怎么处理 |
|---|---|
| **每段最高音的字** | 必须零风险；有风险就改旋律或换落点 |
| **每句（乐句）第一个字** | 优先空拍 / 同音进入，零风险 |
| **大跳（≥5 半音）的落点字** | 降调字不该被上行进入；**阳平被上行进入反而正确** |

★ **总率是荧光笔，"三类位置"才是判官。** 落地例：总倒字率 6.3% 看着不低，
但三类位置**全部零风险**；剩下的 0.08 一档全是 ±1 半音级进，按 §7.2 从宽第 2 条放过。
**唯一保留的 0.17（「唇」被下行 2 半音进入）是 Hook 的形状本身**——
按 §6.4「荧光笔不是判官」+ §6.2「固定搭配语境锁死词」人工确认放过，**并写进交付文档**。

### 第四原则：词先定稿时，韵脚平仄改不了，用旋律补偿

`tone-check.md` §9 的"下句尾用平声"在**词已定稿**时常常不可执行
（言前辙韵脚以去声为主，改字就是改词）。补偿手段两条：

1. **落低音区**（段落末句落到主和弦根音所在的最低音区）；
2. **加长时值**（末字给 1.5–2 拍）。
**"低 + 长"给到的落地感，与"平声"等价。** 并在交付文档里写明哪几处不合、为什么、怎么补的。

### 第五原则：不转调也能做高潮（约束先于手法）

**先看 Suno 的 Exclude 框里有没有 `key change finale`。** 有 → **末遍副歌不许转调**。
替代手法（代价从低到高）：

1. **Hook 整体上移一度**（形状不变、只换起音高度）——最推荐，Hook 身份不丢；
2. 段末加 2 小节器乐扩展；
3. 编制加满（交给 Style 框，不写进词）。

★ **约束先于手法**：Suno 里不能做的，就别在设计阶段做进去，否则要返工。

### 交付物（五项，缺一不可）

| 项 | 说明 |
|---|---|
| **简谱** | 纯文本简谱，**带每 2 小节的和弦行**（和弦按调性算实音名，不写级数） |
| **倒字检查表** | 逐字风险 + 分档处理 + **三类高发位置单独复查** + 刻意保留项的书面理由 |
| **和声进行表** | 每段每小节级数 + 实音 + **段末落音是否落在和弦音上**（逐条核） |
| **`.mid`** | 双轨（旋律 + 和弦），给 DAW / 音频 cover 用 |
| **`.wav`** | 软音源试听版（旋律 + 和弦两层，`numpy` + `soundfile`）——**用户要"填旋律"就是想听** |

配套写 **`.md`**（设计说明 + 倒字 + 和声表）与 **`.txt`**（纯简谱）双份。

### 工具：`scripts/melody_fill.py`（第五个脚本）

```
python scripts/melody_fill.py song.json out/ 曲名     # 一次出 简谱 + 检查 json + .mid + .wav
```

- **音节自动绑定**：数据里音符只写 `(级数, 八度, 时值, 起拍)`，
  **音节从该行歌词逐字绑定**，绑定数与字数不符**直接报错**——防手抄错字。
- **段长两种写法**：行**依次堆叠**（推荐，不必手写每行绝对拍位）或显式 `"bars": N`。
- **多音字 / 轻声覆盖表**：`为`=wéi(阳平，动词)、`得`=de(轻声)……
  **不定音就会判错**（`tone-check.md` §10：同字两读调型相反）。
- **MIDI 纯手写，不依赖 `mido`**（环境里没有也能跑）。

★ **三条工程纪律（都对应真实事故）**：

1. **交付物必须做「词稿回比」** —— 把旋律数据里的字**逐行 `==` 比对**交付稿原文。
   实测：第二遍副歌最初被插在 **Verse 2 之前**，**行数 / 段序 / 字数全一致、只有顺序错位**，
   字数统计和肉眼都漏，**靠回比才露**。
   **判据：回比不是"文本类交付"的专属纪律，凡是从歌词生成的产物（旋律 / 字幕 / 提示词）都要回比。**
2. **数字一律跑脚本**：音域 / 最高音出现在哪个字 / 大跳处数 / 动态 RMS，
   全部用脚本算。本稿曾把"大跳 3 处"写进文档，实算只有 **2 处**（同一个「多→年」+5）。
3. **刻意项必须写下来**：保留的倒字风险、破例的平仄，都要在交付文档里点名 + 给理由。
   **"漏检"和"已知并接受"必须能区分。**

## 写词规则（创作模式共用）

### 动笔前：内部自查清单（2026-09-20 新增）

★ **这张表自己填，不要拿去逐条问用户**（见「核心原则：缺关键信息就一次问清」）——
缺项一律**自己合理默认**，并在交付自检里标明哪几项是推断的。

| 项 | 自己要定下来的 |
|---|---|
| **只说哪一件事** | 用一句人话；说不出来就别动笔（见「道具锚定」） |
| **对谁说** | 词里的"你"是谁；有没有"你" |
| **在哪个时刻** | 说话人站在哪个时间点上（精确到某个具体场景，不是"某天"） |
| **歌的类型** | ★ **默认不是叙事型**。参考分布：态度型 64% / 情境型 24% / 说理型 8% / 叙事型 5%。**类型决定人称与副歌重复预算** |
| **副歌情绪落点** | 最后要停在哪（★ 可以停在难受里，不必解决） |
| **贯穿道具** | 有的话是什么、它每次出现是什么意思 |

**为什么要有这张表**：类型没定就写，会默认滑向"叙事型 + 情绪走完整"——
那正是 AI 味最重的组合（见 `references/ai-tell.md` §1.2）。

### 禁用句式：`no … no …` 排比否定（2026-09-18 新增，用户指定硬禁）

**一句话**：**一行不许出现两个 `no`**。否定是结论，歌要的是证据。

**判据（命中任一即改）**：
1. **同一行 ≥2 个 `no`**：`No money, no time` / `Got no map and got no plan`；
2. **相邻两行都拿 `no` 起头**（跨行排比）：`No more tears` / `No more rain`；
3. **`no one` / `nobody` / `nowhere` / `no way` / `no more` 与 `no X` 成对出现**——
   换了词，清单化没变，同算违规；
4. **豁免**：`ain't no …` **单独**出现不算（蓝调语法特征，是语感资产）；
   但 `ain't no A, ain't no B` 成对 → 违规。

**为什么禁**：一排否定句＝**把情绪列成清单**（我没有什么／我没有什么），
主题从画面降级成数列，而且这种句子能塞进任何一首歌——与「空洞句」同源，
是英文 AI 歌词最高频的机器指纹之一。

**替代写法（不是删掉第二个 `no`，是把它换成证据）**：

| 违规句 | 改法 |
|---|---|
| `Got no map and got no plan` | `The map's soaked through` ＋ `Gas money gone at the county line` |
| `No money, no time` | `The rent's due Friday` ＋ `The tank's on empty` |
| `No more tears, no more rain` | `The rain quit an hour ago` ＋ `I still haven't moved` |

两条通则：
① **一行只留一个否定**，第二处换成**具体动作或物件**；
② **肯定句 + 转折**往往比否定更狠——`I got the whole day and it's still too short`
（先给足，再翻回来，比"什么都没有"更有重量）；
③ **连续三行以上同构否定**（排比清单化）**一票否决**，整段重写。

**边界（别扩大化）**：中文的「没…也没…／不…不…」**不在本禁之列**——
那是汉语自己的对仗手段（`我没有回头　也没有恨` 即此类），**是设计，不是病**。
**本条只禁英文 `no … no …`。** 中文要一并禁，另行说明。

### 命题类主题：道具锚定（2026-09-12 新增，改稿时同样适用）

**什么时候用**：主题句是一句**规律**而非一件事（"人这一生 总有几次要转身""每个人都会…"），
**或用户反馈"意境差了意思 / 不到位"**。

**先诊断——四症状，中一条就要改承载方式**：
1. **通篇时间概述**（"二十岁那年""后来的几年""后来才发现"）——有时间线，没有场景
2. **句子是道理不是画面**（"不是认输 是给自己留一扇门""就不必再硬跟""都离自己更近"）
   ——每句都对，但换成任何一首歌都成立 = 空洞抒情
3. **全曲找不到一件可以摸到的东西**（物象全是半抽象比喻，如"手心"）
4. **主题词退化成口号**（出现次数过多、形态单一）

**解法：给命题找一件贯穿道具。工序是"先定物，再写词"，不是先写句子。**
① 选一件**日常的、可反复出现的物件**（灯 / 门 / 钥匙 / 车票 / 杯子 / 沙发）；
② 定它在 4 个位置上的**状态变化**，这变化本身就是全曲的结构；
③ 才动笔写句子，每段都把镜头对准这件道具。

**一件道具该有的样子**（以"灯"为例，四个位置各一个状态）：

| 位置 | 道具状态 | 语义 |
|---|---|---|
| Verse 1 | 灯亮着，照到夜深 | 还在等，还不肯关 |
| Pre-Chorus | 只有这盏灯知道我在等人 | 对外说的是另一套，只有灯知道真相 |
| Final Chorus | 把灯关了 | 关灯＝终于肯承认结束了 |
| Outro | 灯灭之后，屋子比从前更深 | 灯一关，孤独才显出体积 |

**全曲没写一句"我放下了"，灯的开关把这件事说完了。**
"意境"不是形容词堆出来的，**是道具在几个位置上的变化**。

**配套三件事**：
1. **主题词降噪 + 换形态**。主题词首稿动辄出现 8–10 次，要降到一半以下，
   **且每处形态必须不同**——同一个词分别当"嘴上说的""心里想的""真做了的"来用
   （`又转过身`＝该走没走 / `早就已经转身`＝只是嘴上说 / `真的要转身`＝这次是真的）。
   其中**反向使用**最能提神：先写"我动过几次要走的心／每次站到门口　又转过身"，
   用主题词的反面把它钉住，后面再落正面那次才有力。
2. **道理句改成动作句**。`给自己留一扇门`（道理）→ `有时候关上门　有时候不问`（两个动作，
   一个是空间上的、一个是关系上的，**同一动作的两个层面**）。
3. **抽象的"悟"改成回到现场**。`后来才发现　天比原来更亮`（结论句）→
   走进当年那条巷子、**门牌号码发黄**、站着笑自己荒唐，落点「原来困住我的　就是一道墙」
   （墙既是巷子里真有的墙，也是心里那道）。

**反向检查**：改完后逐段自问"这一段能不能拍出来"——拍不出来的段落，就是要改的段落。

★ **道具找定之后还有一半活**（2026-09-20 新增）：**怎么让它长成一整套词汇**——
意象成系统（同调词生成法）、七种感官的分布、重力法则（先展示后告知），
见 `references/imagery-system.md`。
**判据一句话：这些意象能不能出现在同一个场景里？** 有一个"凭什么在这儿"的，就换掉。

### 题眼自证：三层（2026-09-20 新增）

**"先看题眼字落在哪个韵部"这条只用到了第一层。** 完整的三层是：

| 层 | 做法 | 例 |
|---|---|---|
| **① 字在韵里** | 题眼字所在的韵部 ＝ 主韵。**韵部结构本身就是主题结构**，不必为押韵硬凑字 | "囚禁与脱出"选 **ou**：「牢」「逃」同韵 |
| **② 多题眼 → 多韵部** | 主韵与 Bridge 换韵**各认领一个题眼字**；换韵的位置本身就是内容 | 主题"冬孤独/夏离别/春是桥/秋渗透"：主韵 **ung**（**「風」**在韵里，而"渗透"的本体就是风）+ Bridge **iu**（**「橋」**在韵里，正对"春是桥梁"） |
| **③ ★ 让"例外的那一项"不做韵脚** | 主题里若有**排他句**（"唯独 X""只有 X"），就让 X **全曲藏在句中、一次都不做韵脚**，只在**最后一句**落进格子 | "唯独秋渗透所有季节" → **「秋」出现 4 次全在句中，唯独末句"看得見秋"落在韵脚** |

**第三层是本条最值钱的用法**：**"不在格子里"就是"渗透"在韵脚层面的实现**——
它一直出现在句子里（渗透所有季节），却从不占任何韵脚位（它不是季节之一）；
最后一句落下去，等于宣告渗透完成，歌到此结束。
判据一句话：**主题里那个"唯一的例外"，一旦让它落在韵脚上，主题就被写平了。**

⚠️ 配套纪律：这一处是**刻意的破韵**（末句脱离主韵），必须在交付自检里写明理由
（"收束感降一档 → 悬着"），**不能默默破**——否则与跑韵无法区分。

### 中文
1. **先定韵脚再写词**。硬线是**段内统一**——一段之内不跑韵。
   **段间换韵不但合法，而且是国语流行的多数做法**（语料 n=487：换韵 51%、一韵到底约四成、
   完全不押 9%；说唱换韵 75%，粤语 33%）。判断只有一条：**是不是有意的设计**——
   主歌→副歌换、Bridge 换、按视角换（见模式 D）都是设计；写着写着撞不到韵了就换，是跑韵。
   自检要报的是「段内有没有跑」+「段间这次换韵的理由」，不是「全篇是否一韵到底」。
   ★ **韵有「稳定性」，不只是「押没押」**（2026-09-20 新增）：**完美韵 ＞ 家族韵 ＞
   元音韵（同韵腹不同韵尾）＞ 辅音韵（韵尾相近）**，越靠近完美韵越**收束**，越远越**悬着**。
   用法两条：① 段落收尾、Hook 句要**收束**就用完美韵或家族韵；需要"悬着等下一句"时
   故意降一档。② **换韵型 ＝ 换情绪**——同一段词只把韵型从完美韵降成家族韵，情绪就变了，
   这是**主歌两段旋律必须一样、却要情绪不同时的唯一解法**（同字不动，只换韵型）。
   **故意不押必须写得出理由**，写不出就是漏了。
   ★ 顺带一条反直觉的：**窄辙反而容易出好词**——宽辙字多、随手就能押，
   容易滑向空洞句；窄辙逼你挑字。**不要只挑宽辙。**
2. 只从该韵字族取字。找不到合适字时允许近韵（同韵腹不同韵尾，如 ang/an 通押），
   但一段内最多两处，且不能落在最重要的落点句上。
3. 相邻两行不许用同一个韵脚字；整首歌同一个字最多押两次，且要隔开一整段。
   ⚠️ **豁免：重复段落造成的不算**——副歌逐字重复时，同一个韵脚字会按遍数重复出现，
   那不是复押，是同一段词被唱了三次（语料 27% 的歌副歌各遍逐字全同）。
   **统计复押前先把重复段落折叠成一遍**，否则每条都误报；只有**段内**的重复才计。
   一条易漏的子规则：**同一个字不要在同一段里既做韵脚、又出现在邻近行的句尾**
   ——原稿第 3 行落「就只能**认**」、第 4 行落「对自己**认真**」，
   两处同字相邻，听感是复沓而不是设计。改法：换掉其中之一，**优先换非韵脚那一处**。
   ★ **近重复也算复押**（2026-09-20 新增）：不只是同一个字——**读音极近的字对**同样构成复押，
   英文里最典型（mind / mind、time / time、heart / heart 这类只换词性不换音的），
   中文里是"同字不同搭配"（认 / 认真）。**判据：把两个韵脚字念出来，听起来是不是同一个音。**
4. 押韵位尽量保持声调一致。上声（三声）难拖长音，副歌核心句韵脚优先选
   平声或去声。
   ★★ **有旋律时必须做倒字检查**（2026-09-20 新增）——字调与旋律走向冲突，
   唱出来会**变成另一个字**（"深爱"→"神爱"）。这是**语义跑偏**，不是"难听"的程度问题。
   高发位置三类：**每段最高音的字 / 每句第一个字 / ≥5 半音大跳的落点**。
   判据、计分、从宽从严与五种改法见 `references/tone-check.md`。
   ★ **句尾平仄**：上句尾用**仄**（悬着、催下一句），下句尾用**平**（落定、能拖长）；
   **段落最后一个字的最优解 ＝ 平声 ＋ 开口音**。
5. **禁止空洞抒情**。自检标准：这一句换成任何一首别的歌是否也成立？成立就删。
6. **禁用滥意象**：梦想、远方、光芒、翅膀、绽放、星辰大海、岁月静好、不负韶华。
   也不要拿"泪 / 心 / 痛 / 爱"当韵脚填充物。
7. 回避英文缩写与生僻多音字——AI 演唱和真人演唱的双重事故点。
8. **上声连用必须逐字标调跑脚本，肉眼一定会漏**（2026-09-12 新增）。相邻两字都是上声
   （如「想起」想3+起3、「我早」我3+早3、「手也」手3+也3）会让咬字发紧、并读成一团。
   血的教训：手查时盯着「偶尔」（偶3+尔3），**改成"有时"后又引入了新的「想起」，
   反而漏掉**——是脚本抓出来的。**改一处常会带出新的一处，必须整篇重扫。**
   反向的坑同样要记：
   「只是把沉默」初判为连用其实是**误判**（只3–**是4**–把3，中间隔着去声，不构成相邻）。
   **判断必须落到声调，不能凭语感**；轻声（的 / 了 / 吧 / 们）不算上声，可作为分隔。
   *工程提醒*：脚本里给每行配的**调串必须与正文等长**，并加一条 `len(正文)==len(调串)`
   的断言——曾因调串写短了两位，虚报了「上声作韵脚 1 处」，白查一轮。
   **错的脚本比没有脚本更危险。**
9. **Hook 落在上声字上的补偿设计**（2026-09-12 新增）。上声 Hook 做长音会拐调，
   但有时它恰是歌名兼最有力的短语（一个单字上声动词，如「走」）。此时**不要为了躲声调换掉它**，
   改用三条补偿：① **长句的落点全部让给去声/阳平，只把短句收在上声**；
   ② 靠 `sits slightly behind the beat` 让它落成**半说半唱的短落点**而非长拖音；
   ③ 在自检里**明写这是已知风险**并给出补救顺序（先加 `[Raspy]` / `short clipped
   line-endings`，最后手段才动歌词）。**藏起风险比留一个更好的设计更糟。**
10. **用户给的主题句不为声调负责——拿到先逐字标调**（2026-09-12 新增）。
   命题式主题句（「人这一生……」「每个人都会……」「XX 总会有……」）追求的是**格言的节奏**，
   不追求朗读的顺口，**上声连用是高发区**。实测："人这一生　**总(3)有(3)几(3)**次"
   这个句子里就藏着**三连上声**（"总有几"三个字全是三声），
   照抄进歌必然咬字发紧；只需改「总有」→「总要」（一个字）就全清，
   语义不变甚至更贴（"总有"＝存在，"总要"＝必然）。
   **工序：拿到主题句 → 逐字标调跑一遍上声扫描 → 再动笔。**
   必须在写主歌之前做——主题句通常就是副歌 Hook，它错了整首都要返工。

### 英文
1. 不追求每行押韵。混用 perfect / family（crate–braid）/ assonance（had–glass）/
   consonance（scene–when）/ slant。全 perfect 像儿歌，全 slant 显懒。
2. 用内韵补充行尾韵密度。
3. 按重音节对齐旋律，不按字母数。朗读判断，别扭处即重音错位。
4. 不为押韵扭曲语序（Yoda-speak）。
5. 回避泛滥韵对：love/above、fire/desire、heart/apart、eyes/lies。
6. ★ **Hook 落音与节奏的进阶部分**（第 6–12 条：低音炮 Hook 的元音设计、
   低音配额、元音子类分辨、换意境重跑落音审计、句长独立变量、时态与实词自押细节）
   **已独立成篇** —— 写英文词必读 `references/english-advanced.md`。

13. **禁用 `no … no …` 排比否定**（2026-09-18 新增，用户指定硬禁）。
    同一行两个 `no`、相邻两行都拿 `no` 起头、`no more A, no more B`、
    `ain't no A, ain't no B` —— **一律不许**；`ain't no …` 单独用**不算**违规。
    判据、豁免与替代写法见「写词规则（创作模式共用）· 禁用句式」。

### 结构（中英通用）
- 方括号标段落：`[Intro]` `[Verse 1]` `[Pre-Chorus]` `[Chorus]` `[Verse 2]`
  `[Chorus]` `[Bridge]` `[Final Chorus]` `[Outro]`
- 段落能量跟随动态走向。低开高走 → 主歌留白副歌加满；全程高压 → 短句反复叠加，
  不要先抑后扬。
- Bridge 是全曲唯一允许转向处（换视角 / 换时间 / 换语气）。
- 主歌 2 必须给出主歌 1 没有的新信息。
- ★ **主歌不许"泄掉"它引向的副歌**（2026-09-20 新增，最易犯）：**主歌里不能出现
  紧接着那个副歌的关键短语、核心意象或韵脚词**。副歌是 Hook——
  主歌先说过了，副歌就没有冲击力了。
  自检动作：**把主歌最后 2 行与副歌前 2 行并排放**，有同词、同意象、同韵脚词 → 改主歌。
- ★ **段长有硬上限，按曲风查表**（2026-09-20 新增）：Suno 在段落过长时会**抢拍、
  压缩段落或直接丢行**。上限表（12 个曲风族）、时长↔字数换算、BPM 感知行数、
  主题密度，全部见 `references/section-limits.md`。**交付前必卡。**
- **主歌段行数统一为 4 句（2026-09-13 新增）**：两个主歌必须**等长**；某段到了 6 句就压回 4 句。
  **副歌不受此约束**——副歌行数由"低音落点 / 双 Hook 分工"决定，6 句常是必需品
  （典型分工：前两行落低音、后两行收身份句，删任何一行都会拆掉落音设计）。
  压缩三条铁律：
  ① **韵脚必须成对删**——段内 AABB 是按对存在的，删哪一对都可以，**只删一句立刻留下韵脚孤儿**；
  ② **"全稿最好的一句"与物件锚不动**（先定哪两句不能换，再决定删哪对）；
  ③ 删完复核**主题是否被删反**——删掉的那一行若恰好是"与全曲 Hook 方向相反的一处"
     （Hook 是"回家"，被删的是唯一一句"我不需要地图"），方向就被删平了。

- **极短时长（≤ 90 秒 / ≤ 2 分钟）走「换结构」而不是「压缩」（2026-09-17 新增）**：
  用户说"控制在 N 秒内"时，先算**目标词量**再动手——
  同曲风同人声的前作词量是可靠基准（例：76 BPM 慢摇乡村 ≈ 每 100 秒 140 词）。
  **若目标只有前作的三分之一，不要压缩，要换结构。**
  按功能删段的优先级（每一段先问"这个功能还有没有别的段在承担"）：
  | 删谁 | 条件 |
  |---|---|
  | Pre-Chorus | 它的"承诺 / 铺垫"功能可由副歌里的一个**动作**承担 → 删 |
  | Bridge | 时长不足 2 分钟时没有空间做转折 → 删（副歌就是终点） |
  | Outro | 低音落点已收进副歌 → 删 |
  | 第三次副歌 | 极短版里重复三次会撑破 → 8 行（4×2）就够 |
  **唯一不能动的是副歌里承载低音落点的那两行**——删一行就拆掉落音设计。
  **时长估算要跑脚本**：`小节数 × (60/BPM × 4)`，参数与区间在交付文档里写明，供用户复核。
- Hook 放副歌第一行或最后行，全曲重复 3–4 次，短句 + 强动词。
- **副歌各遍照抄是常态，不是偷懒**（2026-09-18 新增，语料实测）：国语非说唱 n=487 里
  **副歌各遍逐字全同的占 27%**；末遍与首遍差 0 行的 29%、差 1–2 行的 15%、中位差 4 行
  （多半是末遍**加了尾句或扩了一段**，不是重写）。**前两遍相同是听众记住 Hook 的方式，
  不必刻意改字**——把"副歌重复了"当成问题去改，方向是反的。
  真正的问题只有一种：**末遍既没改一个字、也没加尾**——那叫全曲没有任何位置被点亮。
  末遍处理的默认做法（代价从低到高）：
  ① 改 1–3 个字，改在**热点位**（段首或段尾）；
  ② 照抄后**加一个尾句**；
  ③ **韵式不动，只换韵型**——同一段词只把韵型从完美韵降成家族韵，情绪就换了，
     这是主歌两段旋律必须一样、却要情绪不同时的**唯一解法**（`references/rhyme-zh.md`）。
  **整遍重写是少数做法**——等于放弃了前两遍攒下的期待。
- **副歌占全曲两成半到七成，中位近一半**（非说唱中位 0.48、说唱 0.34）。先定副歌几行几遍，
  再算主歌还剩几行：三遍副歌各 8 行 = 24 行，全曲就落在 36–60 行。两条顺手基准：
  **首个副歌应在两段主歌之内出现**（中位在全曲 22% 处），Pre-Chorus（24%）与
  Bridge（33%）都**不是默认配置**，写之前先问要不要。

## 13 项交付自检（每次交付必附）

| # | 检查项 | 判定标准 |
|---|---|---|
| 1 | 韵脚一致性 | **段内**是否跑韵？段间换韵是否**有意的设计**（换了几次、每次什么理由）？**不要求全篇一韵到底**——国语流行换韵占 51%（n=487） |
| 2 | 自押 / 复押 | 相邻行同韵脚字？同一个字超两次？**统计前先把重复段落折叠成一遍**——副歌照抄各遍不算复押 |
| 3 | 声调 | 押韵位声调是否基本一致？ |
| 4 | 字数整齐度 | 段内各行字数差 ≤2（逐行列出字数）。**必须逐字数或跑脚本，不能目测**——「一杯空虛」是 4 字不是 5 字、「唯一的鎖在我心中」是 8 字不是 7 字，目测必错，极差会虚高。★ **但全曲必须另有 ≥1 处"呼吸点"（相邻行差 ≥4）并在文档里点名**——两条同时满足，见「三项人味指标」③ 的调和口径 |
| 5 | 重音节拍 | 朗读有无唱不出的别扭处？ |
| 6 | 空洞句 | 逐句检查能否替换进任何一首别的歌 |
| 7 | 滥意象 / 禁用句式 | 是否触发禁用清单？滥意象词见「中文」第 6 条；英文另核 **`no … no …` 排比否定**（见「禁用句式」），**必须逐行扫，不能凭记忆** |
| 8 | 视角一致性 | 人称、时态全篇统一？ |
| 9 | 段落推进 | 主歌 2 是否带来新信息 |
| 10 | Hook 强度 | 可记忆？重复 ≥3 次？ |
| 11 | 篇幅 | 非说唱 >400 字、说唱 >600 字需确认曲长 ≥5 分钟 |
| 12 | 段落长度 | 有无段落明显拖沓 |
| 13 | 事实一致性 | 基于真实素材时，细节是否与来源一致；**借意类**（取外部作品主旨）还须核"指向性零命中" |

任何一条不过，先改完再交付，并标出改动处。

### ★ AI 味终检 —— 与 13 项并列的第二道闸（2026-09-20 新增）

**13 项问「该做的都做了没有」；这一道问「这词像不像人写的」。两道都过才算完**
——13 项全过的词，照样可能满是 AI 味。

**核心命题**：AI 写的词不是"用词不好"，是**「没有人做过选择」**——
四段词语法正确、押韵工整、意象丰富，**而这四段可以属于任何一首歌**。

**三条最致命的**（读起来都"不错"，所以最难查）：

| # | 症状 | 说明 |
|---|---|---|
| **1** | **名词全是抽象的** | 单行 ≥3 个抽象名词（hope/dreams/light、时光/远方/梦/自由）——每个都对，合起来是空的 |
| **2** | **结构对称到死** | 每段行数字数句法完全镜像。**技术上完美，听感上是表格** |
| **3** | **什么都解决了** | 难过→释怀→祝福走完整。**真人写词经常停在难受里** |
| **4** | **一个"你"都没有**（2026-09-20 新增） | 全篇只有"我"和天气/物件 → **没有关系，只有处境**。真人几乎总有第二个人 |

⚠️ **第 1 条 2026-09-20 据六首经典实测修正**：原写"最直接的 AI 指纹"，**过严**。
实测《追》（林夕 1994）一首用了 **5 个**抽象词（生命／生活／人生／光陰／錯誤），
《一生中最愛》3 个、《似是故人來》3 个。**判据应改为「抽象词有没有被具体动作钉住」**：
- ✅ 「只想追趕**生命**裡一分一秒」——抽象词 + 动作 + 量词
- ❌ 「時光流轉　夢想飛翔」——抽象词悬空
- ⚠️ **反向警戒：全文零抽象词同样是 AI 味**（太具体 ＝ 把所有需要概括的话都躲开了）。
  自写词实测 0 / 0 / 1 个抽象词，**偏的是这一头**。

**十二条完整症状、英文套话清单（`rise above` / `break the chains` 一类）、
以及"十二条全过了还是像 AI"的四个征兆 → `references/ai-tell.md`。**

★ **一个更狠的测试**：**把标题和所有专有名词去掉，给一个不知情的人看——
他能说出这首歌在讲哪一件具体的事吗？** 说不出来就是没落地。

## 中文演唱避坑（生成 AI 人声时）

- **发音风险词**：专有名词、多音字、英文缩写、自造缩写词最易唱错，提前标出。
  手段：音标重拼（`AI` → `A I`）、连字符断音（`研-究`）。
- **长音元音**：需拖长的位置优先开口度大的元音（a / ang / ao），避开 ü、e、i 收尾。
- **一字一音节**：中文按字落拍，字数整齐 = 节奏稳。英文可靠连读吞音弹性处理，
  中文不行，必须守牢字数。
- ★ **英文同形异音词必须逐个定夺**（2026-09-20 新增）：`live` / `read` / `lead` /
  `wound` / `close` / `bass` / `tear` / `wind` —— 同一个拼写两种读音、意思完全不同，
  后端会按最常见那个唱。**按上下文自己定读音，在交付文档里写明取值**（属可自定的细节，不必问）。
- ★ **不要生造缩写**（2026-09-20 新增）：`signal'd` / `TV'd` / `network'd` 这类
  会被读错或直接跳过。**判据：基础词不是代词或标准助动词，就不要缩写它**（写全：`TV could`）。
- **多音字先定读音**——一字两读时调型往往相反，**定读音是倒字检查的前提**
  （见 `references/tone-check.md` §10）。
- 完整发音风险表（含音标重拼、连字符断音、交付前核对动作）见 `references/pronunciation.md`。

## Suno 元标签

> **交付格式默认值**：本 skill 默认交付**纯段落标签版**——只写 `[Verse 1]` `[Bridge]`
> 这类方括号段落名，**不带冒号和英文标签**。元标签是**可选附加物**：除非他明确要求，
> 否则不要塞进歌词正文，需要时另附一份带标签版。
> 歌词交付物给 **.md（含创作说明/改动清单）+ .txt（纯文本，可直接复制）双份**。

| 类别 | 标签 |
|---|---|
| 结构 | `[Intro]` `[Verse]` `[Pre-Chorus]` `[Chorus]` `[Post-Chorus]` `[Bridge]` `[Instrumental Break]` `[Outro]` `[Silence]` |
| 演唱 | `[Whispered]` `[Belted]` `[Falsetto]` `[Harmonies]` `[Choir]` `[Spoken Word]` `[Raspy]` `[Breathy]` |
| 能量 | `[Low Energy]` `[Building Energy]` `[Explosive]` `[Emotional Climax]` `[Gradual Swell]` |
| 氛围 | `[Melancholic]` `[Nostalgic]` `[Intimate]` `[Dark Atmosphere]` `[Euphoric]` |
| 音效 | `[Vinyl Crackle]` `[Rain]` `[Applause]` `[Static]` |

★ **标签预算（2026-09-20 口径厘清）**：先分清两类——
**段落标签**（`[Verse 1]` `[Chorus]` 这类，**每段一个，必须有**）与
**enriched cue**（`[Chorus - First Payoff]` 这类，**整首 4–8 个、每段 1–2 个**）。
原口径「每段最多 5–8 个」应理解为**整首的总预算**；真按每段 5–8 个塞，
一首 8 段的歌会挂 40–60 个标签，**后端会开始忽略它们**。

**三条节制规则**：① 别给每一种人声质感都打标签（**全局人声方向交给 Style 框**）；
② 优先打在结构要点上（intro / Pre-Chorus 抬升 / **第一次副歌** / Bridge 对比 / 末次副歌 / outro）；
③ ★ **生成器忽略标签时，是简化它们，不是加更多**。
**所有 enriched cue 必须嵌在段落标签内部**（`[Bridge - Quiet Contrast]`），
**不要独立成行**——独立成行会被当成额外段落或一句要唱的词。
标签族清单（律动能量 / 质感配器 / 人声表现 / 形式发展 / 曲风形式）与路由见
`references/tag-guide.md`。

不要自相矛盾（同段别同时写 `[Calm]` 和 `[Aggressive]`）。
风格字段与歌词字段都可以放标签，互相强化。
风格描述里不写艺人名——写风格特征：`周杰伦风格` → `中式旋律说唱，钢琴与弦乐
主导，含蓄内敛的男声`。

## Suno 交付格式六条（硬约束，2026-09-18 新增）

上面那张表讲「放哪些标签」，这六条讲**歌词文本本身长什么样**。**每一条都对应一类真实成品事故**，
而且比标签选错严重——标签选错是效果不对，下面这些是**唱出来的东西根本不是你要的**。

| # | 规则 | 写错的后果 |
|---|---|---|
| **1** | ★★ **段内换行 = 乐句边界，是指令，不是排版** | 一句话拆成两行 → 后端读成**两个乐句**、中间会换气；两句话并成一行 → 一个**长乐句**、中间不换气；空行 → 更长的停顿。**所以删行 / 加行就是在改换气点。** 自检动作：**把词按行念出来，每行末尾吸一口气**——念不下来就是分行错了 |
| **2** | ★ **括号 = 和声 / 伴唱** | 圆括号会被理解成**伴唱层**（要伴唱就用它）；**绝不要用括号做注释**。方括号 `[]` 只留给段落标签，别处不要用 |
| **3** | ★★ **词里任何注释、创作说明都会被唱出来** | 在词稿里写「（这里重复三遍）」，后端会**把这句话原样唱出来**。**这是最常见的事故源。** 注释只能进 `.md` 的创作说明，**`.txt` 与 Lyrics 框里一个说明性括号都不能有** |
| **4** | **`[Instrumental Break]` 留标签、但不放词** | 删掉标签 → 后面段落**整体前移**，序列少一格，后端会拿下一个标签去顶这一段该在的位置；标签下面塞词 → 被当成**要唱的乐句**处理。（部分后端写作 `[Instrumental]`，规则完全相同） |
| **5** | **标点能不用就不用，停顿靠分行** | 逗号、句号多数被忽略，但**可能被当作轻微停顿**；省略号、破折号行为不确定。停顿用换行表达更可靠 |
| **6** | **要拖腔就显式写出来** | 后端看不出你想让哪个字拖长。写法是**重复元音**（`a-a-ah`）或用连字符——各后端的实际反应以实测为准 |

**与默认交付格式的关系（重要）**：默认交付是**纯段落标签版**（`.txt`）——
按第 3 条，那份 `.txt` 里**只应有 `[段落名]` 和歌词行本身**，
其余全部（创作说明、改动清单、推断项标注）留在 `.md` 里。
**第 3 条是这条规矩的硬理由，不是洁癖**；第 1 条则意味着**改稿时每一次删行加行都要重算换气点**——
模式 D 的缩短 / 压句流程尤其要吃这条。

## 戏仿 / 改编叠加规则

要改现成的歌时，写词前先做【骨架拆解】：逐行数原词音节 → 标韵式 → 标重音落点
→ 标长音所在元音。新词重音必须对齐原曲重音（可唱性第一约束）；长音位置尽量
匹配原元音开口度（原曲拖 "lOVE" 的 o，新词写 "rOAd" 比 "lIFE" 更贴）；音节
总数允许 ±1–2 个非重读音节浮动；关键位置用单音节词替换最干净（Crime → Code）；
保留少量原句能唤起听众对原曲的记忆；Bridge 段最适合做意象置换。
